\subsection{Experimental Setup}

\textbf{Hardware.}
% \sysname is evaluated on two servers \xiaoxirev{representing a resource-constrained environment and a relatively-abundant resource environment}: \textbf{4$\times$ NVIDIA RTX 4090-24GB} GPUs connected via PCIe 4.0 with an Intel Xeon Gold 6338N CPU (128 cores),
% and \textbf{4$\times$ NVIDIA A100-SXM4-80GB} GPUs connected via NVLink 3.0 with an Intel Xeon Platinum 8369B CPU (128 cores).
\sysname is evaluated on two servers representing a resource-constrained environment and a relatively-abundant resource environment: \textbf{4$\times$ NVIDIA RTX 4090-24GB} GPUs connected via PCIe 4.0 with an Intel Xeon Gold 6338N CPU (128 cores),
and \textbf{4$\times$ NVIDIA A100-SXM4-80GB} GPUs connected via NVLink 3.0 with an Intel Xeon Platinum 8369B CPU (128 cores).

\textbf{Models.}
We evaluate \sysname on \textbf{Qwen3-14B}, \textbf{Qwen3-32B}~\citep{qwen3}, and \textbf{Llama-3.3-70B-Instruct}~\citep{llama3} to cover different model scales.

\textbf{Workflows.}
To cover diverse agent execution patterns, we evaluate three representative workflows: \textbf{ReAct}~\citep{ReAct}, \textbf{Plan-and-Solve}~\citep{Plan-and-Solve}, and \textbf{AgentFlow}~\citep{AgentFlow}.

\textbf{Workloads.}
Our evaluation covers four datasets: \textbf{MBPP}\citep{MBPP}, \textbf{2WikiMultihopQA}\citep{2wiki}, \textbf{NL2Bash}\citep{nl2bash}, and \textbf{Spider}\citep{spider}, corresponding to coding, web search, Bash, and SQL tasks, respectively.

\textbf{Online Traces.}
\label{Traces}
Unlike evaluations based on fixed offline workloads, We use request arrival timestamps from two real-world serving traces, the \textbf{Qwen-Bailian Anonymous Dataset}~\citep{qwen-bailian} and \textbf{Microsoft Azure Traces}~\citep{azure}, to evaluate \sysname under dynamic serving loads. 
The Qwen-Bailian trace exhibits relatively smooth load variation, while the Azure trace shows more pronounced fluctuations. 
Details are provided in~\autoref{online-trace-detail}.

\textbf{Baselines.}
We compare \sysname with \textbf{vLLM Dynamic SD} and \textbf{SGLang Adaptive SD} as adaptive speculative decoding baselines, and \textbf{ThunderAgent} as an agent scheduling baseline.

\textbf{Metric.}
We use average \textbf{Job Completion Time (JCT)} as the primary metric for end-to-end agent latency, defined as the elapsed time from task arrival to completion of the final workflow step.

A detailed analysis of the agent request characteristics and available hardware resources across different serving configurations is provided in~\autoref{request-and-resource-analysis}.

% 说明我们具体是怎么实现 \sysname 的
We extend two state-of-the-art LLM inference engines, vLLM and SGLang, with a runtime SD switching interface, as described in~\autoref{sec:4.1}, and implement \sysname's scheduling mechanism, as described in~\autoref{sec:4.3}, by modifying the scheduler of ThunderAgent, a state-of-the-art agent-oriented task scheduling system.

% 总体介绍实验
We evaluate \sysname under seven configurations covering different models, hardware platforms, and online serving traces, and compare it against four baseline configurations.
\autoref{fig:end2end_jct} shows the average JCT of all methods, which serves as our primary metric for end-to-end performance.

% 分点介绍实验结果

% 不同的请求轨迹
\textbf{Different Request Traces.}
% 如附录所示，两种轨迹具有较大的差异性。 
The Azure and QwenBailian traces exhibit substantially different load patterns (\autoref{Traces}), stressing different aspects of \sysname.
% Azure 轨迹的负载波动较大，其主要考验的是 \sysname 根据不同负载能力选择性使用 SD 加速的策略。
Accordingly, \sysname achieves \textbf{1.18--1.64$\times$} speedup over the best baseline across different models and hardware configurations, demonstrating the benefit of adapting SD usage to changing serving loads.
The Azure trace shows large and frequent load fluctuations, providing opportunities for \sysname to selectively enable SD under favorable loads while avoiding its overhead under high load.
% 而 QwenBailian 轨迹的负载波动较小，长期处于高负载，主要考验的是 \sysname 的任务调度策略。
In contrast, the QwenBailian trace remains at a relatively high load for long periods, leaving fewer opportunities for SD acceleration and placing greater importance on remaining-step-aware scheduling.
Under this sustained high-load setting, directly enabling SD or existing dynamic SD schemes can even increase JCT, whereas \sysname achieves \textbf{1.88$\times$} and \textbf{2.10$\times$} speedups on Qwen3-14B and Qwen3-32B, respectively.
These results show that \sysname benefits from selective SD switching under fluctuating loads, while its scheduling mechanism becomes particularly important under sustained high loads by completing short-remaining jobs earlier, reducing system load, and creating more favorable conditions for subsequent SD acceleration.

% 不同的模型
\textbf{Different Models.}
% 从两个角度切入：不同的参数量，不同的模型家族
\sysname consistently improves end-to-end JCT across variations in both model scale and model family.
For model scale, it achieves \textbf{1.25--2.10$\times$} speedup on Qwen3-14B and Qwen3-32B, and still provides a \textbf{1.18$\times$} speedup when scaling to the much larger model, Llama-3.3-70B-Instruct.
For model family, \sysname remains effective across both Qwen3 and Llama models.
These results show that \sysname is not specific to a particular model scale or family, but persist across heterogeneous LLM serving workloads.

% 不同的环境
\textbf{Different Hardware Platforms.}
% 总起，说明两种环境刚好对应资源受限和资源富足的情况。
Our evaluation covers two substantially different hardware resource regimes.
The 4090-24G platform provides relatively limited GPU memory and low-bandwidth inter-GPU communication, representing a resource-constrained serving environment, whereas the A100-80GB platform provides abundant GPU memory and high-speed NV-Link interconnects, representing a resource-abundant serving environment.

\begin{itemize}[leftmargin=10pt]
    \item 
        Under the resource-constrained setting, limited compute capability and memory resources introduce two challenges that \sysname addresses through its SD switching and scheduling mechanisms, respectively.
        \begin{itemize}[leftmargin=10pt]
            \item 
                The system becomes compute-bound at relatively small running batch sizes, resulting in a low crossover point beyond which SD no longer provides acceleration.
                Consequently, Non-SD is preferred for a large fraction of execution.
                Existing dynamic SD baselines still retain additional SD-related overhead in this regime and can even perform worse than pure Non-SD.In contrast, \sysname performs a more complete runtime switch and incurs lower overhead in Non-SD mode, leading to faster inference and lower average JCT.
            \item 
                Limited KV-cache capacity constrains the runnable batch size and causes more requests to remain queued.
                ThunderAgent primarily optimizes spatial utilization by admitting as many requests as possible within the available memory to maximize throughput, whereas \sysname additionally considers the temporal dimension by prioritizing jobs with shorter predicted remaining execution time.
                This allows \sysname to complete jobs earlier and further reduce average JCT.
        \end{itemize}
    \item 
        Under the resource-abundant setting, abundant KV-cache capacity substantially reduces queueing, while its stronger compute capability increases the break-even load $B^{*}$ (defined in~\autoref{sec:4.1}), allowing SD to remain beneficial under higher serving loads.
        Consequently, there is less room for both scheduling and SD switching optimizations.
        Nevertheless, \sysname still achieves the lowest average JCT, demonstrating its effectiveness even when the optimization headroom is limited.    
\end{itemize}

% 介绍剩余 Step 预测策略的准确率
\textbf{Remaining-Step Prediction Accuracy.}
We evaluate the predictor in~\autoref{sec:4.2} using Accuracy, Pair Accuracy, and Top-10\% Recall, which measure exact remaining-step prediction, pairwise ordering accuracy, and recall of the true shortest 10\% jobs, respectively.
Since our scheduler mainly relies on queue ranking, the latter two metrics are more relevant.
As shown in~\autoref{tab:prediction_performance}, Type-A achieves 100\% accuracy since its remaining steps are explicitly available from the planning prompt, while Type-B benefits from its multimodal step distribution.
Although Type-C is more difficult to predict, state information still provides useful estimates.
Overall, \sysname achieves \textbf{84.1\% Pair Accuracy} and \textbf{82.2\% Top-10\% Recall}, providing reliable signals for scheduling.

% 介绍消融实验

% 对比调度策略
\textbf{Impact of Scheduling.}
We first evaluate the impact of \sysname's remaining-step-aware scheduling.
Compared with ThunderAgent (\autoref{fig:ablation}, 1), adding the \sysname scheduler (\autoref{fig:ablation}, 4) reduces average JCT from 82.5\,s to 55.1\,s, corresponding to a \textbf{1.50$\times$} speedup.
A similar improvement is observed when combined with vLLM DSD (\autoref{fig:ablation}, 2 vs 5), where average JCT decreases from 72.0\,s to 48.2\,s.
These results show that prioritizing jobs with shorter predicted remaining steps is more effective for reducing average JCT than throughput-oriented scheduling alone.

% 对比不同的动态 SD 实现方式
\textbf{Impact of Dynamic SD Mechanisms.}
We next compare different implementations of dynamic SD.
Replacing vLLM DSD with \sysname's runtime SD switching reduces average JCT from 72.0\,s to 64.6\,s under the ThunderAgent scheduler (\autoref{fig:ablation}, 2 vs 3). 
When combined with the \sysname scheduler, the average JCT further decreases from 48.2\,s with vLLM DSD to 44.5\,s with \sysname (\autoref{fig:ablation}, 5 vs 6).
This improvement mainly comes from \sysname's lower overhead in Non-SD mode (see~\autoref{dynamic-sd-comparison}), while preserving comparable performance to the baseline in SD mode.

% 与理想情况的差距
\textbf{Gap to Oracle.}
Finally, we compare \sysname with an oracle configuration that uses oracle remaining-step information for scheduling.
The oracle configuration achieves an average JCT of 43.0\,s, compared with 44.5\,s for \sysname, leaving only a \textbf{3.5\%} gap (\autoref{fig:ablation}, 6 vs 7).
This small gap indicates that the predicted remaining steps are sufficient to achieve performance close to scheduling with ground-truth remaining steps.
